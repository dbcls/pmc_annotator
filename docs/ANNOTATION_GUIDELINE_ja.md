# PMC 識別子 役割アノテーション ガイドライン

_`pmc_annotator` のゴールドスタンダード用、および identifiers.org と合意するための
規約ドラフト。2026-10-27 時点。_

## 1. 目的と範囲

本ガイドラインは、PubMed Central 全文中に見つかった各データベース識別子の出現に対し、
**generated**・**used**・**mentioned** のうち1つの役割を割り当てる方法を定める。
ゴールドスタンダードの注釈の基準であり、かつ identifiers.org と規約を合意するための
基準でもある。これにより、識別子の共起を帰属可能な寄託・再利用イベントへ変換できる。

役割は (論文, データセット, 識別子) の出現ごとに1つ割り当て、**周囲のテキスト窓だけで
判定する（コンテキストのみ判定）**。外部レコードや著者の同一性は参照しない。
（より厳密な判定にはそれらの参照が必要になりうるが、参照できない場合はコンテキストのみの
判定を記録し、その根拠を注記する。）

## 2. 3つの役割

- **generated** — この研究がレコードを産生し、寄託・登録した。功績はこの論文の著者に帰す。
  手がかり: Data Availability / Accession Numbers 節、「deposited」「we sequenced/submitted」
  「has been deposited」。
- **used** — 既存のレコード・参照資源・生物材料を、この研究の入力または材料として用いた。
  功績は元の寄託者に帰す。含むもの: ダウンロード/取得/再解析したデータ、アラインメント先の
  参照ゲノム、プライマー/プローブ/siRNA の設計やコンストラクト構築に使った配列、
  ナンバリング/変異の参照、入手して使った系統/細胞株/クローン。
- **mentioned** — 識別子は実体を命名・注釈・相互参照しているだけで、この論文自身の実験で
  その配列/データを使っていない。

## 3. 判定手順

各出現について、上から順に:

1. この研究がレコードを寄託・登録したか → **generated**。
2. 既存のレコードや材料を入力/材料として取り込んでいるか（規約A・B参照）→ **used**。
3. それ以外（命名・注釈・相互参照・比較リスト）→ **mentioned**。
4. コンテキストだけでは判定できない場合 → **unsure**（真の曖昧性に限る。§6参照）。

## 4. 規約A — used / mentioned の境界（配列・データ）

判定軸は「識別子が命名形で書かれているか」**ではない**（括弧付き accession は両側に
共通して現れる）。軸は**「論文がその配列/データを実際に処理したか」**である。

**`used` となるのは**、論文が配列やデータを自らの手続きに投入したとき:

- それを元にプライマー / プローブ / siRNA / shRNA / ガイドを設計した;
- それからクローニング / サブクローニング / コンストラクト・ベクター構築を行った;
- それにアラインメント / マッピングした、または BLAST / 検索のクエリに使った;
- ナンバリング / 変異の参照に使った（「designations based on NM_198056.2」）;
- それが指し示すデータセットを再解析した（例: 本研究で解析した GEO series）。

**`mentioned` となるのは**、識別子が次のいずれかにのみ現れるとき:

- 命名・注釈の記述（「X (NM_...) にはイントロンがない」「mRNA NM_... の遺伝子産物」）;
- 相互参照ポインタ（「GEO sample GSM... に記載」「accession no. GSE...」で当該データの
  解析は行っていない）;
- **比較・相同性リスト** — BLAST ヒット表、%identity 表、オルソログ/パラログ列挙、
  系統の種リスト — で、accession が比較対象の実体を命名するだけで、その配列をここで
  処理していないことが窓から明らかな場合。論文がそのレコードを産生／処理した可能性を
  窓から排除できない場合は、mentioned ではなく §6 の **unsure** とする。

括弧形はラベルを決めない。プライマーとしての「GAPDH (NM_204305) ggagtcaac...」は
**used**、「LAMA2 (NM_000426), lacking an intron in mouse」は **mentioned**。

## 5. 規約B — 物理材料の入手

リポジトリや企業から何かを入手したときは、**識別子が何を指すか**で切る:

- 識別子が、入手して使った材料そのものを指す（系統・細胞株・クローン・アレル）→ **used**。
  例: 「BACE(−/−) mice (MGI:2389228) were obtained from Jackson Laboratory」→ **used**。
- 入手物が別物（抗体・物理構造・キット）で、識別子は標的の実体を命名するだけ → **mentioned**。
  例: 「Creb3L2 (accession no. NP_919047) were obtained from Aviva Systems Biology」
  （入手したのは抗体、accession はタンパクの命名）→ **mentioned**；
  「downloaded from PDB. GenBank identifiers: Rattus Kv1.1, NM_173095」
  （入手したのは構造、GenBank ID は配列の注記）→ **mentioned**。

## 6. エッジ規則

- **「The data from those …」定形 → generated。** コンテキストのみ判定では、寄託 accession に
  付随する「The data from those experiments / samples …」のような表現は、周囲が再利用とも
  読めても、論文自身が産生したデータを示す。より厳密には外部レコードと著者関係の確認が
  必要だが、それが無い場合は generated がコンテキストのみ判定として妥当。
- **GEO 寄託 vs 再利用。** 論文自身が産生したデータについて「available in GEO (GSE...)」と
  述べるものは **generated**、第三者データセットを論文が解析する同じ表現は **used**。
  §2 の寄託手がかりで切り分ける。
- **ドメイン / ファミリー registry**（Pfam, InterPro, COG, SMART, TIGRFAM, ...）は
  ほぼ常に注釈 → **mentioned**。論文がそこからプロファイルを構築・検索した場合を除く。
- **`unsure` は保守ラベル。** 窓だけでは `generated` または `used` を排除できない出現に
  付与する。識別子を命名のみと確定できず、かつ論文がそのレコードを産生／処理した可能性を
  排除できないときは、mentioned に落とさず断定を保留する — これにより寄託・再利用の
  過小計上を防ぐ。典型: %identity 列挙・BLAST ヒット表など密な比較・相同性テーブルで、
  列挙された accession が論文自身のレコードまたは処理した入力でありうる場合。テキストが
  積極的に支持するときのみ確定ラベルを優先する。
  （既知の課題: 現行の分類器はこうしたケースを `mentioned` に寄せがちで、これは本ラベルが
  防ごうとする過小計上の方向。分類器の unsure 的文脈の扱いの整合は §8 の未決事項。）

## 8. ステータスと未決事項

本ガイドラインは、used / mentioned の改修後の現行ゴールドスタンダード（221件）で用いた規約を
反映する。identifiers.org と確認すべき事項:

- GEO の寄託 vs 再利用の表現（generated vs used）;
- 比較・相同性リストを `used` と数える余地があるか（規約A は現状「数えない」。
  generated/used を排除できない窓は `unsure`）;
- 分類器の `unsure` 的文脈の扱いの整合（現状 mentioned に寄る＝過小計上の方向）。
